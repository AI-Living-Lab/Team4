# GDPO 학습 가이드 (VS2+ / Qwen2.5-VL)

`gdpo_trainer.py` 로 **video_SALMONN2_plus (VS2+)** 모델을 GDPO(GRPO 변형) 강화학습하는 방법을 정리한 문서입니다.
SFT 로 학습한 multi-segment temporal grounding 정책을, temporal-IoU 기반 reward 로 RL 미세조정합니다.

---

## 1. GDPO 개요

GDPO 는 GRPO(Group Relative Policy Optimization)를 VS2+ 멀티모달(비디오+오디오) temporal grounding 에 맞춰 구현한 트레이너입니다.

학습 1 step 의 흐름:

1. **Generate** — 한 샘플 프롬프트로 `num_generations`(기본 8)개의 답변을 샘플링 (`do_sample`, `temperature`, `top_k=50`).
2. **Reward** — 각 답변을 GT 시간구간과 비교해 reward 계산. **채널 구성은 reward 모듈이 결정**(§9).
   - 기본(`reward_functions`) = `[format, iou]`. 세분화(`reward_functions_rM_sep`) = `[format, len, global, local]`.
   - `format` : `"From <tX><tX><tX><tdot><tX> to ... ."` 포맷 준수도.
   - `iou`/`global`/`local` : MUSEG `r_M` 또는 그 분해(global NGIoU/F1 + local NGIoU) temporal grounding 점수.
3. **Advantage** — 그룹 내 reward 를 **채널별로** 정규화(`(r - mean) / (std + eps)`) 후 가중합해 GDPO advantage 계산.
   채널을 분리할수록 각 신호가 단위분산으로 보존됨(세분화 reward 의 핵심 이점).
4. **Loss** — clipped surrogate `-min(r·A, clip(r,1-ε_low,1+ε_high)·A)` − `beta`×KL.
   기본은 clip-higher 경로(ε_high≥ε_low). `clip.num_iterations(μ)=1` 이면 r≈1 → 순수 GDPO 와 수치 동일(§5.1).

reward 형식은 답변이 아래 토큰 포맷을 따른다고 가정합니다 (UnAV-100 multi-segment QA):

```
From <t0><t0><t3><tdot><t3> to <t0><t0><t5><tdot><t6>. From <t0><t0><t9><tdot><t1> to <t0><t1><t0><tdot><t0>.
```

## 4. 두 가지 학습 경로 (자동 분기)

`model_path` 가 무엇이냐에 따라 트레이너가 자동으로 경로를 선택합니다.

### 경로 A — SFT adapter 이어학습
- `model_path` = **SFT LoRA adapter 디렉터리** (`adapter_config.json` 존재)
- `model_base` = time-token base 모델
- 동작: adapter 를 base 위에 로드 후 **RL 학습대상을 제한** — `LoRA(q/k/v)` + `embed_tokens` + `lm_head` 만 학습. `o_proj` LoRA / `visual.merger` / `audio.*` 는 freeze (SFT 멀티모달 grounding 보호).
- ref 모델: adapter `disable_adapter()` = pre-SFT base.
- ⚠️ 이 경로에서는 **`config.lora.enabled` 를 `false`** 로 둘 것 (이미 PeftModel 에 LoRA 이중 적용 방지).

### 경로 B — fresh LoRA (config.yaml 기본값)
- `model_path` = `model_base` = **SFT-머지 모델** (`adapter_config.json` 없음)
- 동작: 머지 weight 위에 **새 RL LoRA** 를 씌움 (`config.lora` 설정 사용). 비-LoRA 파라미터는 자동 freeze.
- ref 모델: LoRA `disable_adapter()` = SFT 정책 (KL 기준이 SFT).
- `config.lora.enabled: true` 필요.

## 5. `config.yaml` 설정

```yaml
model:
  model_path: ${SFT_CKPT}     # placeholder — 보통 CLI --model_path 로 덮어씀 (경로A=adapter / 경로B=머지모델)
  model_base: ${BASE_MODEL}   # placeholder — 보통 CLI --model_base 로 덮어씀 (time_tokens 포함 VS2+ base)
  tti_mode: "off"             # off | on  (§7 참고)

data:
  dataset_path: ${TRAIN_DIR}/unav100_v2.json

lora:                         # 경로 B(fresh LoRA)에서만 사용
  enabled: true               # 경로 A 면 false 로!
  r: 32
  lora_alpha: 64
  lora_dropout: 0.05
  train_embeddings: false     # embed_tokens 를 modules_to_save 로 full-train (lm_head 와 독립)
  train_lm_head: false        # lm_head 를 modules_to_save 로 full-train. 둘 다 false=LoRA(q/k/v/o)만

gdpo:
  num_generations: 8          # 그룹당 샘플 수 (advantage 정규화 단위)
  max_completion_length: 256  # 생성 최대 토큰
  beta: 0.04                  # KL 계수 (0 이면 ref 모델 비활성)
  temperature: 1.5            # 샘플링 다양성
  reward_weights: [1.0, 1.0]  # 채널 가중치. 길이는 reward 모듈 채널 수에 자동정렬 (§9).
  multi_seg_weight: 1.0       # [sep2] GT>=2 prompt advantage ×w. 1.0=off. >1=multi-seg 붕괴 대응 (§9.1).

clip:                         # DAPO clip-higher (§5.1). config.yaml 기본은 OFF.
  enabled: true
  epsilon: 0.2                # ε_low
  epsilon_high: 0.28          # ε_high (>ε_low = clip-higher)
  num_iterations: 1           # μ. 1=clip 미작동(=기존 GDPO). >1 로 켜면 clip 작동 (grad_accum>1 과 병행 가능).

training:
  num_train_epochs: 1
  max_steps: 1000             # >0 이면 epoch 무시 (smoke-test/길이제한)
  per_device_train_batch_size: 1
  gradient_accumulation_steps: 4
  learning_rate: 5e-6
  warmup_ratio: 0.05
  lr_scheduler_type: cosine
  bf16: true
  seed: 2024
  gradient_checkpointing: true
  gradient_checkpointing_kwargs:
    use_reentrant: false

logging:
  logging_steps: 1
  save_steps: 100
  save_total_limit: 5
  report_to: wandb            # tensorboard 도 가능

ref_model:
  enabled: true
```

> CLI 인자가 config 보다 우선합니다(`--model_path`, `--max_steps`, `--tti_mode`, `--reward_module`, `--run_name` 등).

### 5.1 clip-higher (DAPO) — `config.clip.*`

DAPO clip-higher 가 trainer 에 통합돼 있습니다. clipped surrogate loss:

```
loss = -min( r·A,  clip(r, 1-ε_low, 1+ε_high)·A )      r = exp(logp_new - logp_old)
```

- `ε_high > ε_low` (예 0.28 vs 0.2) = upper clip 완화 → 저확률 토큰 확률 상승 여지를 남겨 **탐색/엔트로피 붕괴를 지연**.
- **`num_iterations`(μ) 가 핵심**: 한 rollout 을 μ 번 정책 업데이트에 재사용해야 old↔new 정책이 갈라져 `r≠1` → clip 이 실제 binding. `μ=1` 이면 `r≈1` → **순수 GDPO 와 수치적으로 동일**.
- ✅ **[통합] `μ>1` + `grad_accum>1` 병행 가능.** block-repeat sampler(`[p0..p_{N-1}]×μ`, N=grad_accum×num_gpu)가 μ iteration 사이에 `optimizer.step()` 을 보장하므로 `r≠1` 이 유지된다. 더는 `grad_accum=1` 을 강제하지 않음. effective batch = `grad_accum × num_gpu`. (⚠️ μ>1 캐시는 rollout 을 N개 동시 보관 → 메모리 ~N배. OOM 시 grad_accum↓ 또는 gradient_checkpointing=true.)
- 진단 메트릭: wandb 에 `ratio`(평균 r), `clip_frac`(clip 비율), `gen_entropy`(생성 엔트로피), `advantage_*` 로깅 → μ>1 에서 실제 binding / 붕괴 여부 확인.

| config | clip 상태 | grad_accum | 비고 |
|--------|-----------|-----------|------|
| `config.yaml` | **OFF** (`μ=1`) | 4 | 팀 공용 기본 — 기존 GDPO 와 동일 동작 |
| `config_clip.yaml` | ON (`μ=2`) | 1 | clip-higher 단독 실험 |
| `config_clip_sep.yaml` | ON (`μ=2`) | 1 | clip-higher + 세분화 reward(rM_sep) |
| `config_clip2_sep2.yaml` | ON (`μ=2`) | 2 | clip-higher + sep2 + **grad_accum>1**(block-repeat). GPU 2개 기준 |
| `config_clip2_sep2_mu1.yaml` | OFF (`μ=1`) | 2 | sep2 + 큰 배치(grad_accum>1), 순수 GDPO |

### 6.6 백그라운드 실행 (SSH 끊겨도 유지: `setsid nohup`)

```bash
echo "started pid=$!"
```

| 인자 | 설명 | 기본값(미지정 시) |
|------|------|-------------------|
| `--config`        | config.yaml 경로 | (없음) |
| `--model_path`    | SFT adapter(경로 A) 또는 머지 모델(경로 B) | `config.model.model_path` |

| `--run_name`      | wandb/tracker run 이름 | `config.logging.run_name` 또는 output_dir basename |
| `--tti_mode`      | `off` / `on` (§8) | `config.model.tti_mode` 또는 `off` |
| `--reward_module` | reward 모듈명 (§9) | `config.reward.module` 또는 `reward_functions` |
| `--resume_from_checkpoint` | `True`=자동 / 경로=특정 / 미지정=처음부터 | None |
| `--val_path` | [VAL] 검증셋 JSON. 주면 `save_steps`마다 평가(§10). 강제 ON | `config.val.dataset_path` / `val.enabled` (기본 **OFF**) |

> `--model_path` 와 `--dataset_path` 는 (config 포함) 반드시 채워져야 합니다. 없으면 에러로 종료합니다.

## 8. `tti_mode` (Time-Token Interleaving)

모델 config(`time_token_id_range`)와 데이터셋 입력(`tti_time_format`)이 **반드시 짝이 맞아야** 합니다.

| `tti_mode` | 모델 config | 데이터 마커 | 사용 상황 |
|------------|-------------|-------------|-----------|
| `off` | `time_token_id_range = None` 으로 강제 | 마커 미삽입 (`tti_time_format="off"`) | 데이터에 time marker 인터리빙이 없을 때 (기본) |
| `on`  | base config 유지 / 머지모델은 토크나이저에서 복원 | `special_token` 인터리빙 | 비디오/오디오 청크 사이에 time marker 가 삽입된 데이터 |

`off` 인데 base 에 `time_token_id_range` 가 남아 있으면 rope_index 가 항상 ON 분기를 타 `IndexError` 가 날 수 있어, 트레이너가 자동으로 `None` 처리합니다. 두 값이 어긋나면(desync) 경고가 출력됩니다.

## 9. Reward 모듈 선택

`--reward_module`(또는 `config.reward.module`)로 trainer 복제 없이 reward 구현만 교체합니다.

### 채널 호환 규약 (`load_reward_module`)

trainer 는 채널 이름/개수를 하드코딩하지 않습니다. reward 모듈이 자기 채널을 선언하고 trainer 는 그대로 따릅니다 — **새 채널을 가진 reward 모듈을 추가해도 trainer 무수정.**

1. **`REWARD_CHANNELS` 선언 (권장, 임의 채널)** — 모듈이
   `REWARD_CHANNELS = [(name, fn, needs_gt), ...]` 를 정의하면 그대로 사용 (채널 수·이름·순서 자유).
   `needs_gt=True` → `fn(completion, gt)`, `False` → `fn(completion)`.
2. **convention fallback (레거시)** — `REWARD_CHANNELS` 가 없으면 함수명 규약으로 조립:
   필수 `format_reward`+`iou_reward`, 옵션 `timestamp_reward`/`modality_reward`(CoT, 있을 때만).

자동 처리(수정 불필요): `reward_weights` 길이는 채널 수에 맞춰 자동정렬(부족분 1.0 패딩 / 초과분 절단),
wandb 메트릭은 채널 `__name__` 으로 자동 로깅(`rewards/format`, `rewards/len`, …).

| 모듈 | 채널 | 특징 |
|------|------|------|
| `reward_functions` (기본) | `[format, iou]` | iou = MUSEG `r_M` = ½(r_G + r_L). union-global NGIoU + 위치순 local NGIoU |
| `reward_functions_rM_fp`  | `[format, iou]` | iou = `r_M − K·n_unmatched_pred` (FP 페널티 → precision 복원) |
| `reward_functions_prec`   | `[format, iou]` | iou = `r_M − λ·outside_ratio` (시간단위 precision 페널티) |
| `reward_functions_rM_cov` | `[format, iou]` | iou = `r_M − γ·coverage_excess` (길이편향/통짜 억제) |
| `reward_functions_f1`     | `[format, iou]` | iou = F1(best-match) 베이스라인 |
| **`reward_functions_rM_sep`** | `[format, len, global, local]` | 학습신호 세분화(§9.1). global=**MUSEG F1(precision 내장)**, len/local 분리 → **multi-seg 붕괴 대응** |
| **`reward_functions_rM_sep2`** | `[format, len, global, local]` | rM_sep 의 sep2 변형 — `len`=graded + multi-pred1 floor. `config_clip2_sep2.yaml` 와 함께 (§9.1) |
| `reward_functions_rM_fp_cot` | `[format, iou, timestamp, modality]` | `<think>/<answer>` CoT 답변용 (4채널) |
| `reward_functions_cot_p2` / `p3` | `[format, iou, timestamp]` | CoT 변형 (3채널) |
| `reward_functions_cot_p4` | `[format, iou]` | CoT 변형 (2채널, content reward 없음) |

> CoT(`<think>...</think><answer>...</answer>`) 데이터로 학습할 때도 **별도 트레이너 불필요** —
> 통합 `gdpo_trainer.py` 에 `--reward_module reward_functions_rM_fp_cot`(또는 `_cot_p2/p3/p4`)
> 와 CoT 데이터셋만 지정하면 된다. reward 모듈이 `<answer>` 블록을 직접 파싱하므로 트레이너는
> raw completion 만 넘긴다. (config: `config_cot.yaml` / `_p2` / `_p3` / `_p4`.)

### 9.1 `reward_functions_rM_sep` — 학습신호 세분화 (multi-seg 붕괴 대응)

학습이 진행될수록 모델이 **multi-segment 를 못 뱉고 1개로 수렴**하는 문제를 겨냥한 4채널 reward.
GDPO 가 채널을 따로 정규화하는 점을 이용해 신호를 분해합니다.

| 채널 | 내용 | 의도 |
|------|------|------|
| `format` | 응답 전체가 `From <t\d>{3}<tdot><t\d> to <t\d>{3}<tdot><t\d>.` 나열이면 1.0, 아니면 0.0 | strict 하되 **개수 중립**(정형 세그먼트가 여러 개여도 1.0 → 개수 억제 안 함) |
| `len`    | pred 세그먼트 개수 == gt 개수 → 1.0 (기본 binary) | 개수 신호 명시. `LEN_REWARD_MODE=graded` → `1-|n_pred-n_gt|/max` (near-collapse gradient 생존) |
| `global` | **MUSEG F1** = 2PR/(P+R), P=overlap/Σpred, R=overlap/Σgt | precision 항 내장 → "한 개 큰 세그먼트" attractor 제거 |
| `local`  | 세그먼트별 NGIoU **best-match** 평균 / max(n_pred, n_gt) | 위치 품질 + over/under 개수 페널티. 정렬-순차보다 robust |

- `reward_weights` 권장: `[1.0, 1.0, 1.0, 1.0]` (= `[format, len, global, local]`).
- ⚠️ reward 설계는 **붕괴 예방**용. 이미 무너진 그룹은 채널 std≈0 → advantage≈0(GDPO 구조 한계).
  **회복엔 clip-higher(§5.1) + temperature/num_generations(탐색 유지)가 함께** 필요.
- **`gdpo.multi_seg_weight`(sep2)**: GT≥2 prompt 의 (정규화된) advantage 를 ×w 해 gradient mass 를
  키워 single 편향(데이터 prior 4:6)을 상쇄. `1.0`=off(기본), `1.5` 권장. clip-higher on/off 무관.
- **`lora.train_lm_head`**: `embed_tokens`/`lm_head` 를 개별 토글(둘 다 modules_to_save). sep2 실험은
  보통 `train_embeddings:false` + `train_lm_head:true`.
- 사용: `--reward_module reward_functions_rM_sep`(또는 `reward_functions_rM_sep2`) /
  `config_clip_sep.yaml` / `config_clip2_sep2.yaml`.

## 10. Validation 셋 평가 & checkpoint selection (toggle)

학습 중 **검증셋으로 자동 평가**해 두고, 끝난 뒤 **best 체크포인트를 사후 선택**하는 기능.
체크포인트마다 수동으로 test 를 돌리던 비효율을 없앤다. 기본 **OFF** (이전 config·호출과 100% 호환).

> **왜 early-stop 이 아니라 selection 인가** — RL 보상곡선은 non-monotonic·noisy 라
> `700↓→1000↑` 같은 지연 점프가 흔하다. 작은 patience 로 조기종료하면 후반 회복을 죽인다.
> 그래서 학습은 끝까지 돌리고 val 로 **best step 만 사후 선택**한다(late-peak 절대 안 놓침).

### 켜는 법 (toggle)

| 방법 | 동작 |
|------|------|
| 아무것도 안 함 | **OFF** — 기존 학습과 byte 단위 동일 |
| `--val_path <val.json>` | 강제 **ON** |
| `config.val.enabled: true` + `val.dataset_path` | **ON** |

config `val:` 블록 (예: `config_sep2fp_lr_val.yaml`):

```yaml
val:
  enabled: true
  dataset_path: ${BASE_ROOT}/data/val/unav100_tail_val150.json
  max_new_tokens: 256
  max_time: 999.9
  natural: false        # CoT(<answer>) 출력 파싱이면 true
```

### 동작

- `save_steps` 마다(`on_save`) **현재 메모리 정책으로 greedy 생성** (reload/LoRA-merge 0 → 거의 공짜).
  멀티 GPU 면 샘플을 rank 에 샤딩 후 `gather_object` 로 합산.
- 지표 = **segment mIoU(pairwise)** 와 **pairwise F1_avg(θ=0.1/0.3/0.5/0.7/0.9)** 의 **평균 = `combined`**.
  정의는 `eval/eval_miou.py` 의 pairwise 블록과 1:1 동일(트레이너 안에 복제).
- 결과: `output_dir/val_metrics.jsonl` (step별 append) + wandb (`val/combined`, `val/seg_miou`, `val/f1_avg`).
- 학습은 **절대 중단 안 함**(early-stop X) — 콜백은 평가·기록만 한다.

### val 셋 만들기 (video-disjoint 필수)

train 과 **video 가 겹치면 누수**라 selection 이 망가진다. `data/val/make_val_split.py` 가
`unav100_tail.json` 에서 **video 단위**로 ~150개를 떼어 train·test 와 disjoint 하게 분리한다
(스크립트가 `val/test video overlap: 0` 을 검증·출력. train(unav100_v2)↔tail 은 이미 교집합 0).

```bash
python data/val/make_val_split.py    # → data/val/unav100_tail_val150.json (+ test 잔여본)
```

### best 선택 (학습 종료 후)

```bash
python _tools/GDPO/select_best_ckpt.py <output_dir>
#  step별 combined 표 + BEST step + 그 step 하나만 test 로 최종평가하는 명령까지 출력
#  --smooth ema|ma3  : 노이즈 peak 방지(스무딩 후 best)
#  --metric seg_miou|f1_avg : 선택 기준 변경 (기본 combined)
```

→ 기존 "체크포인트마다 다른 GPU 로 수동 full-test" 가 **학습 중 자동 val + 최종 1회 test** 로 줄어든다.

### 주의

- **greedy(val) ≠ sampling(train)** — val 은 deterministic, 학습은 temperature 샘플링. val 곡선이
  sampled reward 와 항상 일치하진 않는다(0-start·단일seg 붕괴가 *eval 아티팩트*였던 전례 있음).
- **비용** — eval 1회 ≈ (val 크기 / GPU 수) 회 생성. 150개·2GPU·save 10회면 학습에 수십 분 추가.
  무거우면 `val.dataset_path` 를 더 작게 하거나 `save_steps` 를 키운다.
- val 은 train 과 **video-disjoint**, test 와도 disjoint 여야 한다.
- val 평가도 학습과 **동일 환경/런처**(trl 필요)에서 같은 프로세스로 돈다 — 별도 GPU/환경 불필요.

### 디버그 env 요약

| env | 효과 |
|-----|------|
| `TTI_DEBUG=1` `TTI_DEBUG_STEPS=3` | rank-0, 첫 N step TTI 정합성 계측 |
| `LEN_REWARD_MODE=graded` | `reward_functions_rM_sep` 의 `len` 채널을 graded 로 (기본 binary) |
| `FP_PENALTY_K=0.2` | `reward_functions_rM_fp` 의 FP 페널티 계수 |

### 자주 겪는 이슈

- **`IndexError` (rope_index)** — `tti_mode=on` 인데 데이터에 마커가 없거나, base config 의 `time_token_id_range` 와 데이터가 desync. `tti_mode` 와 데이터셋을 맞추세요.
- **LoRA 이중 적용 경고** — 경로 A(adapter)인데 `config.lora.enabled: true`. `false` 로 변경.
- **OOM** — `num_generations` / `max_completion_length` 축소, `gradient_checkpointing: true` 유지(긴 멀티모달 시퀀스에 필수).
- **resume 시 RNG `UnpicklingError`** — 트레이너가 numpy global allowlist 로 자동 우회합니다(`torch>=2.4` 대응).
- **multi-segment 붕괴(학습할수록 1개로 수렴)** — 원인 ①현 `iou`(NGIoU, precision 없음)가 "한 개 큰 세그먼트"를 보상 ②GDPO 그룹정규화로 붕괴 후 std≈0 → gradient 소멸. 대응: `reward_functions_rM_sep`/`_sep2`(global=F1, len/local 분리, §9.1) + `gdpo.multi_seg_weight`>1(GT≥2 advantage 가중) + clip-higher(§5.1) + temperature/num_generations 로 탐색 유지. `[GDPO SAMPLES]` 의 `len` 채널/세그먼트 수로 조기 감지.
- **clip 이 안 걸리는 듯(`ratio≈1`, `clip_frac≈0`)** — `num_iterations(μ)=1` 이면 clip 미작동. `μ≥2` 로 설정(`config_clip.yaml` / `config_clip2_sep2.yaml`). [통합] grad_accum>1 과 병행 가능 — block-repeat sampler 가 μ 사이 step 을 보장하므로 `ratio≠1` 유지(§5.1). 단 LR 이 매우 작으면(예 5e-6) 한 step policy 변화가 작아 ratio 가 clip 경계에 거의 안 닿을 수 있음 → 그땐 μ=1(`config_clip2_sep2_mu1.yaml`)로 순수 GDPO + 큰 배치가 합리적.
