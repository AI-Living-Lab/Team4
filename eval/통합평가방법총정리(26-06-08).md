# 통합 평가 방법 총정리 (2026-06-08)

multi-segment temporal grounding 평가를 **런처 1개 + 평가기 1개**로 통합했다.
기존의 난립하던 런처(`eval_salmonn2plus*.sh`, `*_nochunk*.sh`, `*_merged*.sh`)와
부수 분석 스크립트(`analyze_segments`, `posteval_gtlen`, `lib_tvg`, `reeval_from_results`,
`eval_all_miou_multiseg*` …)는 전부 제거되었다.

## 파일 구성 (이게 전부)

| 파일 | 역할 |
|---|---|
| [eval.sh](eval.sh) | 통합 런처. 추론(+resume) / 평가를 한 스크립트로. |
| [eval_miou.py](eval_miou.py) | 통합 평가기. 결과 → 3종 summary JSON. |
| [_chunk_helpers.py](_chunk_helpers.py) | 청크 split/append/resume 보조 (런처가 호출). |
| [config.yaml](config.yaml) | 추론/평가 하이퍼파라미터 (flat `KEY: VALUE`). |

## 1. 산출물 — 3종 summary JSON

각 결과 폴더에 아래 3개가 생성된다. **구조는 동일**하고 `method` 와 mIoU/Recall에
쓰는 IoU 계산법만 다르다.

| 파일 | method | mIoU 정의 |
|---|---|---|
| `pairwise_miou_summary.json` | `pairwise` (MUSEG 방식) | GT 세그먼트별 **best-match** pred IoU → 샘플 평균 |
| `union_miou_summary.json` | `union` (기존 방식) | GT 세그먼트 vs 겹치는 pred **합집합** IoU → 샘플 평균 |
| `sample_miou_summary.json` | `sample` (R-AVST all_iou) | 전체 GT merge vs 전체 pred merge **샘플당 1개** IoU |

### 스키마 (예시)

### metric 정의

> 집계 단위는 기존 `eval_all_miou_multiseg.py` 의 해당 block 과 **수치가 일치**하도록 맞췄다.
> (Best_IoU/Union_IoU 의 **GT세그먼트 단위**, All_IoU 의 **샘플 단위** block)

- **mIoU**
  - `pairwise` = Best_IoU **(GT세그먼트 단위)**: 전체 GT 세그먼트를 한 풀로 모아 평균
    (세그먼트별 best-match pred IoU).
  - `union` = Union_IoU **(GT세그먼트 단위)**: 〃 (세그먼트별 union-IoU).
  - `sample` = All_IoU **(샘플 단위)**: 샘플당 all_iou 1개를 샘플 평균.
- **Recall @θ** = 해당 단위에서 `(method-IoU ≥ θ)` 비율 → 기존 R@1 과 동일.
  - `pairwise`/`union`: `(IoU≥θ인 GT세그먼트 수)/(전체 GT세그먼트 수)`.
  - `sample`: `(all_iou≥θ인 샘플 수)/(전체 샘플 수)`.
- **Precision @θ** = pred 측 단위에서 `(IoU ≥ θ)` 비율.
  - `pairwise`/`union`: `(IoU≥θ인 pred세그먼트 수)/(전체 pred세그먼트 수)`.
  - `sample`: All_IoU 는 대칭 집합 IoU 라 P=R=F1 (= all_iou≥θ 샘플 비율).
- **F1 @θ** = `2·P·R/(P+R)`. `*_avg` = 5개 threshold(0.1/0.3/0.5/0.7/0.9) 평균.
- **FP/FN** (세 파일 공통, overlap=best-match 기준):
  - FN@θ = best-match IoU < θ 인 GT 세그먼트, FP@θ = best-match IoU < θ 인 pred 세그먼트.
  - `_rate_%` = 전체 세그먼트 대비 비율, `n_*_segments` = 카운트.

> 참고: `pairwise` 의 IoU 는 MUSEG `nncore.ops.temporal_iou` 의 멀티세그 일반화,
> `sample` 의 IoU 수식은 R-AVST `compute_tiou`(전체 merge 후 inter/union)와 동일하다.

## 2. 파싱 규칙

### pred 파싱
- **기본**: SALMONN 시간 토큰 `From <t..> to <t..>. ...` 만 파싱.
- **`NATURAL=on`** (`eval.sh`) / **`--natural`** (`eval_miou.py`): 관대 파싱.
  시간토큰 + `HH:MM:SS` + `M:SS` + `X.X-Y.Y`(소수 초) + `from X to Y seconds` +
  `second{X} to second{Y}` + `first N seconds` 등 다양한 출력을 최대한 회수.
- **`PRED_PERCENT=on`** / **`--pred_percent`**: pred 구간을 **영상 길이 대비 %(0~100)** 로 보고
  결과 항목의 `duration` 필드를 곱해 초로 환산 (avicuna 류). `--duration_key` 로 필드명 변경.
- **CoT 출력**: `<answer>...</answer>` 태그가 있으면 **그 안의 내용만** 파싱 (자동 감지, 기본/natural 공통).
- 비정상 구간(`end ≤ start`)은 보수적으로 최소 0.1초만 부여 (점수 이득 최소화).

### GT 소스 자동감지 (우선순위)
명시 인자가 없으면 결과 파일을 보고 자동 선택한다.

1. **`--gt_ref` / `GT_REF=on`** (강제): 각 항목의 `ref`(SALMONN 시간토큰)에서 GT 파싱.
2. **embedded**: 모든 결과 항목에 `gt_segments` 가 있으면 그대로.
3. **ref(auto)**: 모든 항목에 `ref` 가 있으면 토큰 GT 로 자동 사용.
4. **`--test_json` / `TEST_JSON=` 또는 리프명 test_json**: `<test_dir>/<리프>.json` 의 `gt_segments`.

> **중요**: ref/embedded 가 test_json 보다 **우선**이다. 둘 다 '각 샘플 자신의' GT 라
> 순서/매칭 문제가 없기 때문. test_json 은 `(basename(id/video), gt_label)` 키 매칭 →
> gt_label 없으면 video 단독(모호하지 않을 때) 매칭. **묵시적 positional 은 금지**
> (순서 어긋난 결과에서 엉뚱한 GT 와 비교하는 사고 방지). 정말 순서가 같다고 확신할 때만
> `--allow_positional` 로 명시 허용. 매칭 실패분은 `gt=[]` 로 제외하고 `[WARN]` 출력,
> GT 자체를 못 찾으면 그 파일만 `[SKIP]`.

## 3. 런처 `eval.sh` 사용법

`KEY=VALUE` 인자. config.yaml 값은 자동 로드되고 CLI 가 우선.

### 주요 인자

| 인자 | 기본값 | 설명 |
|---|---|---|
| `MODE` | `infer` | `infer`=추론+평가 / `eval`=이미 있는 결과만 평가(**GPU 불필요**) |
| `CHUNK` | `off` | `on`=청크 추론(+자동 resume) / `off`=단일 JSON |
| `CHUNK_SIZE` | `500` | (참고용; split 은 `_chunk_helpers.py` 로 미리 수행) |
| `STAGE` | `sft` | `sft` \| `gdpo` |
| `CKPT_MODEL_ID` | — | LoRA 모델 ID (`$CKPT_DIR/$STAGE/$CKPT_MODEL_ID`) |
| `CKPT_STEP` | latest | 숫자/`checkpoint-N`, `base`(=base모델), `root`(루트 adapter) |
| `BASE_MODEL_ID` | `video_salmonn2_plus_7B_time_tokens` | base 모델 경로 |
| `MERGED_MODEL` | — | full-merged 체크포인트 직접 로드 (LoRA 머지 X, `STAGE/CKPT_*` 무시) |
| `TEST_JSON` | — | `CHUNK=off`/`MODE=eval` 의 GT(+추론 입력) JSON |
| `TESTSET` | — | `CHUNK=on` 의 chunks 디렉토리 이름 (`$TEST_DIR/$TESTSET/`) |
| `TESTSET_TAG` | 자동 | summary `testset` 필드 / 출력 경로 태그 |
| `RESULTS` | — | `MODE=eval` 에서 평가할 결과파일 또는 폴더(재귀) |
| `OUT_DIR` | 자동 | 결과 저장 폴더 (생략 시 규칙대로 생성) |
| `LABEL` | 자동 | summary `label` 필드 (기본 = CKPT_MODEL_ID) |
| `NATURAL` | `off` | `on`=관대 파싱 |
| `GT_REF` | `off` | `on`=GT 를 `ref`(토큰)에서 파싱(강제). off=자동감지 |
| `PRED_PERCENT` | `off` | `on`=pred 를 %로 보고 duration 곱해 초 환산 (avicuna) |
| `GPUS` | `0` | `0` 또는 `0,1` |
| `TTI_TIME_FORMAT` | config | `off` \| `special_token` \| `natural_text` \| `from_to` |
| `CONFIG` | `config.yaml` | 로드할 config 파일명 |

### 출력 경로 규칙

```
$EVAL_DIR / <branch> / fps<N>_<format> / <TESTSET_TAG> /
  branch = <stage>/<CKPT_MODEL_ID>/<CKPT_FOLDER>   # base+LoRA
         = base/<BASE_MODEL_ID>                     # CKPT_STEP=base
         = merged/<MERGED_MODEL 폴더명>             # MERGED_MODEL=
$EVAL_DIR 기본 = /workspace/outputs  (OUT_ROOT 로 변경)
```

### 사용 예

```bash
# 1) base+LoRA, 단일 JSON 추론+평가
bash eval.sh STAGE=gdpo CKPT_MODEL_ID=sft_7b_unav_v8_rl_v2_rMsep_clip_mu2 CKPT_STEP=1000 \
     BASE_MODEL_ID=base/salmonn2p_7b_puvalor_off_v2 \
     TEST_JSON=/workspace/data/test/unav100_v2_500.json GPUS=0

# 2) 청크 추론 (대용량; data/test/<TESTSET>/chunk_*.json 필요)
bash eval.sh CHUNK=on STAGE=sft CKPT_MODEL_ID=salmonn2p_7b_unav_baseline CKPT_STEP=1500 \
     BASE_MODEL_ID=base/video_salmonn2_plus_7B_time_tokens TESTSET=unav100 GPUS=0

# 3) full-merged 체크포인트 직접 평가 (LoRA 머지 X)
bash eval.sh MERGED_MODEL=/workspace/checkpoints/base/salmonn2p_7b_puvalor_off_v2 \
     TEST_JSON=/workspace/data/test/unav100_v2_cot_50.json GPUS=0

# 4) 이미 추론된 결과만 재평가 (GPU 불필요). CoT/자연어면 NATURAL=on
bash eval.sh MODE=eval RESULTS=/workspace/outputs/.../test_results_rank0.json \
     TEST_JSON=/workspace/data/test/unav100_v2_500.json NATURAL=on \
     LABEL=sft_7b_unav_v8_rl_v2_rMsep_clip_mu2
```

### 청크 사전 준비 (`CHUNK=on` 일 때 1회)

```bash
python3 _chunk_helpers.py split \
    --test_json /workspace/data/<원본>.json \
    --chunks_dir /workspace/data/test/<TESTSET>/ \
    --chunk_size 500
```
청크 추론은 `.chunk_idx`/master 길이로 **자동 resume** 되고, chunk 0 의 LoRA merge 결과는
`.merged_model/` 로 캐시되어 이후 chunk 에서 재사용된다(성공 시 자동 정리).

## 4. 평가기 `eval_miou.py` 직접 사용

런처 없이도 결과파일/폴더만으로 평가 가능 (GPU 불필요).

```bash
# 단일 결과 파일
python3 eval_miou.py <out_dir>/test_results_rank0.json \
    --test_json <GT.json> --label <모델명> --testset <태그>

# 폴더 재귀 (하위 모든 test_results_rank0.json 평가, 각 옆에 3파일 생성)
python3 eval_miou.py <out_root> --test_json <GT.json>

# CoT/자연어 출력
python3 eval_miou.py <...> --test_json <GT.json> --natural
```

| 인자 | 설명 |
|---|---|
| `results` (위치) | `test_results_rank0.json` 또는 하위 재귀 탐색할 폴더 |
| `--test_json` | GT json (강제). 생략 시 GT 자동감지 (§2 참고) |
| `--test_dir` | 리프명 GT json 탐색 디렉토리 (기본 `<WS>/data/test`) |
| `--gt_ref` | GT 를 각 항목 `ref`(토큰)에서 파싱 (강제) |
| `--natural` | 관대 파싱 (기본 off = 시간토큰만) |
| `--pred_percent` | pred 를 %로 보고 `duration` 곱해 초 환산 (avicuna) |
| `--duration_key` | `--pred_percent` 환산용 필드명 (기본 `duration`) |
| `--label` / `--testset` | summary 라벨/태그. `--testset` 생략 시 리프 폴더명 자동 |
| `--max_time` | 초 clamp 상한 (기본 9999.9; config 의 MAX_TIME 전달 가능) |
| `--progress_log` | JSONL 스냅샷 append (청크 진행 추적용) |
| `--quiet` | 콘솔 리포트 억제 (summary 는 그대로 생성) |

### 이종 포맷(base 모델) 재평가 예시 (추론 없이)

```bash
# embedded gt_segments + 자연어 pred (arc/chronus/museg): natural 만
python3 eval_miou.py outputs/base/ChronusOmni --natural

# avicuna: pred 가 % → duration 환산
python3 eval_miou.py outputs/base/Avicuna/... --natural --pred_percent

# salmonn2p(토큰 GT in ref): ref 자동감지됨. 강제하려면 --gt_ref
python3 eval_miou.py outputs/base/salmonn2p_7b_timetoken/... --natural

# gdpo 전체 재귀 (ref-format/ id-format 혼재 → 자동감지). 토큰 모드라 --natural 불필요
python3 eval_miou.py outputs/gdpo
# 리프명이 testset 과 다른 경우(*_samp, promptsweep)는 --test_json 으로 지정
python3 eval_miou.py outputs/gdpo/.../unav100_v2_500_samp --test_json data/test/unav100_v2_500.json
```
